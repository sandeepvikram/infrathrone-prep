MASTER EXAMPLE 1: SR Flow Failure (CRM Connector Issue)

🎯 Use This For:

Explaining technical issues • Handling unhappy users • Working with ops/service teams

🎯Situation

SR routing flow suddenly started failing at Conduent. LRDS back-office team raised it urgently because several SRs were stuck in "Pending Routing."

They're not technical, so the frustration was mainly because they couldn't see what was blocking their queue.

📌Task

My responsibility was two-fold:

  • Investigate quickly without panicking the team
  • Communicate clearly at each step, because the LRDS team had to keep working while I diagnosed the issue

I wanted to be proactive, keep them in the loop, and make sure the explanation didn't sound too technical.

🔍 My Standard RCA Path:

  1. Run History → Open Failed Run
  2. Check Trigger Inputs
  3. Check CRM Connector Outputs
  4. Check Conditions / Parse JSON actions
  5. Validate Connection References
  6. Identify error codes (this case: 400 – Bad Request)

⚡Action

Step 1 – RCA Path Execution

Inside Power Automate:

Flow → Runs → Failed Run → Expand "Get Row (CRM)" → Show Raw Inputs/Outputs

I saw the CRM connector started returning empty fields for CaseOwnerId and Department because a CRM update changed the schema.

Step 2 – Explain to Non-Technical Team

"The system is trying to read two fields that were recently renamed in CRM, so the automation can't decide where to route the SR. I'm updating the mapping now — I'll give you a checkpoint in 10 minutes."

I kept updates every 10–15 minutes. This kept them calm. They appreciated that I wasn't hiding anything.

Step 3 – Fix

Inside the flow:

  • Opened Parse JSON → Edit Schema
  • Added the new CRM fields
  • Updated all dynamic content references
  • Re-saved and ran a manual test on a dummy SR

Step 4 – Validate

Once re-run, the flow completed and moved the SR to the correct queue.

Step 5 – Close the Loop

"It's fixed. CRM changed the field names this morning. I've updated the flow mapping and added a defensive check so this won't break again."

✅ Result

  • SRs started moving within minutes
  • LRDS team said the explanation made sense and reduced their stress
  • Added a pre-validation check in the flow so missing fields trigger a graceful fail instead of blocking the queue
  • Built trust because I stayed calm, proactive, collaborative, and transparent
  • Reduced similar failures by 80% over the next few weeks

💡 Keywords Used:

Clear communication Proactive updates Translating technical to non-technical RCA path Connector outputs Schema change Collaboration with ops Building trust Calm under pressure

  1. Power Automate Run History
    • Check HTTP call output
    • See error code (403 Forbidden)
    • Check whether SP item was updated
  2. Azure Portal
    • Function App → Monitor → Invocation Logs
    • Check if request reached the function
    • Errors showed: "AuthorizationFailed – AppRoleAssignmentMissing"
  3. Azure AD → Enterprise Applications
    • Found the Managed Identity lost Mail.Send and Directory.Read.All permissions after tenant security hardening

⚡Action

Step 2 – Explain to Client in Simple Language

"The automation couldn't talk to Microsoft 365 because one of the permissions silently expired during a security update. The system basically said 'you're not allowed to do this'. I'm fixing it now."

This kept them calm and confident.

  • We re-assigned the necessary Graph API permissions
  • Re-granted admin consent
  • Restarted the Function App
  • Back in Power Automate → refreshed the connection reference
  • Ran a manual replay with a test item

Step 4 – Preventive Improvement

I added:

  • A Try/Catch scope in Power Automate
  • Logging to a separate SP list: FunctionStatus, StatusCode, ErrorMessage
  • A daily lightweight test-run to detect permission expiry early

✅ Result

  • Approvals resumed within 40 minutes
  • Client appreciated the calm, structured explanation

MASTER EXAMPLE 1: LRDS Flow Classification Issue

🎯 Use This For:

"Something failed" • "Incomplete info" • "How you solved a problem" • "Recurring issue" • "RCA path"

🎯Situation

One morning we noticed several SRs routed to the wrong team — LRDS got penalty-related SRs and the Penalty Team got general queries.

There was no error in Teams or Outlook, but the pattern looked wrong.

This is the kind of issue where the symptoms appear in operations, not in the system, so you don't get direct technical clues.

📌Task

My responsibility was:

  • Identify what caused the mis-routing
  • Fix it quickly before the queue became worse
  • Prevent the same mistake from happening again

This required both technical debugging and talking to ops calmly to gather context.

⚡Action

Step 1 — My RCA Path (Always Same Structure)

I followed my usual diagnostic flow:

  • Power Automate → Run History → Filter → Last 10 Runs
  • For each run: expand Trigger Inputs, Decision Condition, Classification Step, Routing Logic (Switch)

Technically everything ran "green," which meant system didn't see it as an error.

Step 2 — Investigate Classification Step

I zoomed in on the tile classification logic in the flow.

Inside the flow:

  • Open Action → "Get CRM Row → Description"
  • Check dynamic content passed into "Condition: contains('Penalty')"

The CRM description field had changed — instead of "Penalty", the new template used "PCN" (Penalty Charge Notice).

The automation was looking for the old keyword, so it routed based on a partial match.

Step 3 — Validate by Checking CRM Change Logs

I opened:

CRM → Settings → Audit Summary → Entity: Case → Fields: Description Template

Confirmed that the templates were updated by the CRM config team earlier that week.

Step 4 — Fix

Inside the flow:

  • Updated the match logic to search for both "Penalty" AND "PCN"
  • Added a fallback case: if neither exists → route to a verification bucket
  • Wrapped the condition in a clean Compose + Contains block for readability

Step 5 — Communicate with Ops

"CRM changed their wording, so our automation wasn't catching penalty cases correctly. I've updated the logic and added a fallback check so this won't happen again."

✅ Result

  • Mis-routing stopped immediately
  • 15+ SRs were corrected within minutes
  • Added a fallback to prevent similar failures
  • LRDS appreciated the clarity and said the fix reduced their manual correction work by 30%
  • I documented the change and proactively informed the CRM team, strengthening cross-team trust

💡 Soft Skills Shown:

Proactive thinking Structured problem-solving Calm communication Collaboration with CRM Ownership
MASTER EXAMPLE 2: Azure Function 500 Error (Internal Logic Failure)

🎯 Use This For:

"Incomplete information" • "Major failure" • "Big RCA" • "Debugging Azure + PA" • "Prevent recurring issues"

🎯Situation

In my freelance automation, one day the Azure Function started returning 500 Internal Server Error whenever the final approval stage was executed.

Power Automate only displayed "BadGateway," so the error wasn't obvious.

Employees were stuck because the function controlled the final decision update.

📌Task

I had to:

  • Find where the logic failed inside the Azure Function
  • Check whether it was a data issue or function issue
  • Fix it without breaking production requests
  • Communicate clearly to the client team so they knew what to expect

🔍 My RCA Path for Multi-System Failures:

  1. A. Power Automate → Run History
    • Expand HTTP action
    • Saw: "502 BadGateway"
    • No useful body → means issue is deeper
  2. B. Azure Portal → Function App → Monitor
    • Looked at invocation logs
    • Found stack traces showing null reference inside one of the routing conditions
  3. C. Azure Application Insights
    • Filtered for failed requests
    • Confirmed the null object was ManagerEmail

⚡Action

Step 2 – Identify the Real Issue

The function assumed ManagerEmail always exists, but one department had recently changed their manager structure — some profiles didn't have the field populated yet.

This created an incomplete payload to Graph API → Function crashed → PA showed "BadGateway."

Step 3 – Fix

I collaborated with the cloud engineer:

if (string.IsNullOrEmpty(managerEmail)) { ... route to default escalation ... }
  • Added logging for missing fields
  • Updated the routing rules to handle this exception

Back in Power Automate:

  • Modified the HTTP call to expect the new structured response
  • Added a Condition: If FunctionStatus = "EscalatedDueToMissingData" → route differently

Step 4 – Communicate with the Client

"The function assumed every employee record had a manager email, but HR hadn't completed all updates yet. I've added a safety net in the function and updated the flow so it handles these cases automatically."

I kept them updated throughout using simple statuses:

'Found the issue' → 'Fixing now' → 'Testing' → 'Resolved'

Step 5 – Prevent Recurrence

  • Added daily validation to check incomplete HR profiles
  • Added a monitoring row in SP for all escalated cases
  • Added proper try/catch with meaningful messages

✅ Result

  • The workflow became more stable and handled incomplete data gracefully
  • No further 500 errors after the fix
  • Client appreciated how I explained "backend crash" in simple words
  • Improved success rate of final approval stage from 93% → 99%
  • Built strong trust because I handled a sensitive failure calmly and professionally

💡 Soft Skills Shown:

RCA method Structured investigation Collaboration Proactive prevention Effective communication Clear breakdown of complex concepts

MASTER EXAMPLE 1: High-Volume SR Failures + BAU Pressure

🎯 Use This For:

Handling pressure • Juggling multiple issues • Taking ownership • Staying calm • Prioritizing work • Managing expectations

🎯Situation

One evening in Conduent, around 4:30 PM, our SR automation flow for the LRDS team started failing intermittently during the busiest window.

Ops pinged saying "queue is building up, cases aren't routing correctly."

At the same time:

  • I had new BAU checks pending
  • A CRM template change was deployed earlier that morning
  • Two other flows had minor warnings

This was a genuine pressure situation because SRs must be processed within the SLA window to avoid penalties.

📌Task

My responsibility was to:

  • Keep the queue stable
  • Find what was causing the intermittent routing failures
  • Communicate clearly to ops
  • Prevent escalation

Essentially: stay calm, prioritize correctly, and handle it end-to-end.

⚡Action

Step 1 — Prioritization (Critical vs Non-Critical)

I divided the issues in 30 seconds:

Issue Priority Reason
LRDS routing failure P1 Direct SLA impact
CRM warnings P2 Non-breaking
Other flow warnings P3 No user impact

This helped me stay structured instead of panicking.

Step 2 — RCA Path for the P1 Failure

I followed my usual RCA checklist:

  • Power Automate → Run History → Last 20 runs
  • Failures only in Decision → Apply Routing Rules
  • Expanded each failed run
  • Checked: Trigger Inputs, CRM Record Data, Switch Condition

Saw that "CaseCategory" field was suddenly null in some records

Went to: CRM → Audit Logs → Case Entity

Confirmed CRM team ran a configuration update 2 hours earlier. New cases didn't get category stamped immediately.

So the routing logic was failing because it couldn't classify the SR without the category.

Step 3 — Fix Under Pressure

Inside the flow:

  • Added a pre-validation step
  • "If CaseCategory is null → route to TemporaryValidationBucket"
  • Added a quick log entry into SP: SR number, missing fields, timestamp, fallback route
  • Re-ran the flow for the 7 failed SRs

Step 4 — Proactive Communication

"The case category field isn't being populated on some SRs after the CRM update. I've added a safety check so these SRs don't fail and they go to a temporary queue. No SR will breach SLA now."

Kept them updated every 10 minutes.

Step 5 — Weekly Improvement

After pressure dropped, I worked with CRM:

  • Added a mandatory field validation
  • Added shared documentation
  • Updated the routing logic to handle future nulls gracefully

✅ Result

  • Queue stabilized within 12 minutes
  • No SR breached the SLA window that evening
  • Ops appreciated the calm updates
  • Routing failures dropped from 11% → 0% after the fix
  • Director called out the stability improvement in the weekly meeting

💡 Soft Skills Demonstrated:

Calmness Prioritization Collaboration Ownership Communication Structured thinking

📌Task

My responsibility:

  • Triage both issues
  • Solve the production-critical one first
  • Keep the client calm
  • Prepare the system for a demo within the next 24 hours

I classified issues:

  • Issue A – Azure Function 429 → P1 (blocks core routing logic)
  • Issue B – Approval delays → P2 (annoying but not a blocker)
"Let me stabilize the function first so routing stays reliable. Approvals can be optimized right after."

This calmed them down because they saw a clear plan.

Followed my multi-system RCA method:

Step 3 — RCA for Approval Delays

Inside Power Automate:

  • Found that certain managers were overloaded in approval stage
  • Their Outlook throttled notifications

  • Added Teams notification fallback
  • Added reminder logic for pending approvals >2 hours
  • Set a default escalation rule for demo

Sent a structured update:

"Routing is stabilized, function throttling fixed, retry logic added. Approvals now have a fallback and escalation. Your demo tomorrow will run without interruptions."

✅ Result

  • Function stabilized with zero 429s

  • UAT demo went smooth
  • Client appreciated the structured plan and said the calm handling built a lot of trust
  • They extended the project by another 3 weeks

"Learn something quickly" • "How do you approach learning new tech?" • "Recent achievement you're proud of"

🎯Situation

When I took on the freelance approval automation project, the client wanted the routing logic handled in Azure Functions because the rules were too complex for Power Automate alone.

I had used Azure before, but I'd never built a function that:

  • Called Microsoft Graph
  • Used managed identity
  • Returned structured JSON to PA
  • Followed enterprise-style error handling

The timeline was tight, and I didn't want to deliver a half-baked solution.

📌Task

I had to:

  • Learn Azure Function basics quickly
  • Understand Graph endpoints for user/manager lookups
  • Ensure identity & permissions were correct
  • Integrate the function smoothly with Power Automate
  • Keep the client updated while learning on the go

I wanted to show that I could pick up new tech independently without compromising delivery.

I took a practical, hands-on approach:

  • Read Microsoft docs on Function Apps + Graph

So I learned:

✅ Result

SCENARIO 1: Flow Suddenly Starts Failing in Production

🎯 Use This For:

"What would you do if a flow starts failing in Prod?" • "How do you approach incidents?" • "What's your troubleshooting method?"

🎯Situation

Let's say our Conduent SR Processing Flow starts failing at scale — multiple "Failed" runs appear in the run history, and SRs aren't updating in CRM.

This affects real customer cases (crossings, LRDS submissions), so SLA impact is real.

📌Task

My responsibility is to react calmly and follow a structured RCA path:

  • Contain the issue
  • Minimize impact to Ops
  • Diagnose the fault properly
  • Keep stakeholders informed
  • Fix → Validate → Prevent

I don't panic or make blind changes — I follow the same structured approach every time.

⚡Action

Step 1 — Immediate Containment

Proactively communicate on Teams:

"I've picked up the SR flow failures — starting RCA, will update every 10 minutes."

This alone reduces stakeholder stress.

Step 2 — RCA Step 1: Run History Analysis

I open Power Automate → Solutions → SR Flow → Run History:

  • Filter last 10 failed runs
  • Open one failure → check Inputs / Outputs
  • Check HTTP codes:
    • 403 = identity issue
    • 429 = throttling
    • 400 = bad payload
    • timeout = CRM delay

Most Prod failures reveal themselves at this step.

Step 3 — RCA Step 2: Check Connector Health

Navigate: PPAC → Environments → Connections

I check whether:

  • The service account connection expired
  • DLP recently changed
  • CRM had a schema update (field removed/renamed)
  • The connection reference is mismatched after deployment

This is a proactive habit — I ALWAYS check connectors early.

Step 4 — RCA Step 3: Validate Downstream System

I check CRM Audit Logs:

  • Any overnight maintenance?
  • Any API throttling?
  • Any new required field on the SR entity?

If needed, I collaborate with the CRM admin:

"Can you confirm if the SR table was updated today? My flow is failing on PATCH."

Step 5 — Apply Fix

Depending on cause:

  • Expired SA connection → reauthenticate
  • CRM field update → update JSON body + solution layer
  • Throttling → add delay + concurrency control
  • Null fields → add pre-validation condition

Step 6 — Controlled Testing

I always test in:

  • Dev with sample SR
  • Pre-Prod with real-structure SR
  • Promote to Prod only after sign-off

✅ Result

  • Issue resolved within 30 minutes
  • Missed-SLAs reduced for that shift
  • Added pre-validation checks so the same failure doesn't happen again
  • Documented RCA in Confluence
  • Ops thanked me for clear communication / calm handling

💡 Soft Skills Shown:

Structure Communication Composed behavior Collaboration Ownership Proactive prevention
